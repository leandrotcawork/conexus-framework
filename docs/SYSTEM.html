What Is Conexus?

Conexus (also written Co-Nexus) is Leandro's personal AI agent infrastructure. It runs 24/7 on Fly.io in São Paulo (gru region) and communicates exclusively via Telegram. All agents share the same core: LiteLLM routing, SQLite memory, a Markdown wiki, and APScheduler for proactive tasks.

Reactive Message Flow

What happens when you send a message to Ana on Telegram — from tap to reply.

Tool-calling loop: Ana can call up to 6 LLM turns per message. Each turn may invoke one or more tools (Calendar, Memory, Todos, Wiki). The final turn with no tool calls produces the reply text.
sequenceDiagram participant L as Leandro (Telegram) participant BOT as TelegramBot participant MAIN as _handle_ana_message participant LLM as LiteLLM / Gemini participant TOOLS as AnaTools participant DB as SQLite participant GCAL as Google Calendar L->>BOT: Text or voice message BOT->>BOT: Authorize (check chat_id) BOT->>MAIN: handler(body, prefix) MAIN->>DB: chat_recent("ana", limit=10) MAIN->>DB: facts_list() MAIN->>MAIN: Build system prompt + messages[] loop Up to 6 turns MAIN->>LLM: completion(model, messages, tools=14) LLM-->>MAIN: response MAIN->>DB: log_call (tokens, context="reactive") alt LLM calls a tool MAIN->>TOOLS: _execute_tool(fn_name, args) TOOLS->>DB: read/write facts/todos TOOLS->>GCAL: calendar CRUD TOOLS-->>MAIN: JSON result else LLM returns final text MAIN->>DB: chat_append(user + assistant) MAIN-->>BOT: reply text end end BOT-->>L: reply_text(reply)

Full sequence: Telegram tap → tool-calling loop → reply

Proactive Message Flow

When the scheduler fires a job, messages are sent to Leandro without any triggering request.

Idempotency: Every job writes to ping_log as a write-ahead log. If the process crashes after sending but before marking as sent, it re-sends on restart. This ensures no message is silently dropped.
sequenceDiagram participant SCHED as ConexusScheduler participant JOB as Job fn participant PING as ping_log (SQLite) participant TOOLS as AnaTools participant LLM as TrackedLLM participant BOT as TelegramBot.send_message SCHED->>JOB: run() JOB->>PING: ping_was_sent(kind, ref_id)? alt Already sent JOB-->>SCHED: return (idempotent — skip) else Not sent yet JOB->>PING: ping_mark_pending() JOB->>TOOLS: calendar_list_events / todos_list JOB->>LLM: complete(prompt) LLM-->>JOB: text JOB->>BOT: send_message(text) JOB->>PING: ping_mark_sent() end

flowchart LR A["Agent code\njobs / reactive handler"] -->|"complete(messages)"| B["TrackedLLM\ncore/llm/router.py"] B -->|"litellm.completion()"| C["LiteLLM\nprovider abstraction"] C <-->|HTTPS| D["Gemini API\ngemini-2.5-flash"] B -->|"log_call(tokens)"| E["UsageTracker\n→ SQLite llm_usage"] E -->|"compute_cost()"| F["pricing.py\nUSD/1M tokens"]

LLM call path with usage tracking

How it works

1. Agent calls llm.complete(messages) (proactive jobs) or litellm.completion(tools=...) directly (reactive).
2. TrackedLLM tries the primary provider, falls back to secondaries if configured.
3. On success: logs tokens, cost, context, and duration to llm_usage.
4. On failure: logs the error and tries the next fallback.

Context tagging: Every LLM call is tagged with a context label (reactive, briefing, recap, etc.) via a Python ContextVar. The /uso command shows cost broken down by context.

How to Add a New Agent

Adding a new agent (e.g. Researcher) requires five steps. The pattern is identical to Ana.

1

Create the agent directory

agents/researcher/
├── __init__.py
├── SKILL.md
├── tools.py
└── jobs.py
2

Write SKILL.md

Frontmatter defines the persona, LLM, schedules, and budget. The markdown body is the system prompt.

---
name: Researcher
role: News and research analyst
language: pt-BR
goal: >
  Monitorar notícias e fornecer pesquisas aprofundadas.
tools:
  - web_search
  - memory_get
  - wiki_write
llm:
  provider: gemini
  model: gemini-2.5-flash
  temperature: 0.2
schedules:
  - { kind: news_digest, cron: "0 8 * * *" }
budget:
  daily_usd: 0.50
  monthly_usd: 12.00
  on_exceed: notify
---
# Researcher — system prompt here
3

Write tools.py

A @dataclass bound to SqliteStore, WikiStore, and any external clients.

from dataclasses import dataclass
from core.memory.sqlite_store import SqliteStore
from core.memory.wiki_store import WikiStore

@dataclass
class ResearcherTools:
    store: SqliteStore
    wiki: WikiStore

    def web_search(self, query: str) -> list[dict]:
        # call search API
        ...

    def memory_get(self, key: str) -> str | None:
        return self.store.fact_get(key)

    def wiki_write(self, path: str, content: str) -> dict:
        self.wiki.write(path, content)
        return {"ok": True}
4

Write jobs.py

One make_<kind>_job builder per schedule. Each returns an async def run() closure.

def make_news_digest_job(
    tools: ResearcherTools,
    llm: TrackedLLM,
    send_telegram: Callable[[str], Awaitable[None]],
) -> Callable[[], Awaitable[None]]:
    async def run() -> None:
        # query news, run LLM, send digest
        ...
    return run
5

Wire into main.py

Load the skill, build the LLM, instantiate tools, register jobs, add prefix routing.

# In amain(), after Ana block:
researcher_skill = parse_skill_file("agents/researcher/SKILL.md")
researcher_llm = build_llm(LLMConfig(...), tracker, "researcher")
researcher_tools = ResearcherTools(store=store, wiki=wiki)

# Add tool schemas (same pattern as _ANA_TOOLS_SCHEMA)
_RESEARCHER_TOOLS_SCHEMA = [...]

# Register jobs
scheduler.add_job(JobSpec(
    "researcher", "news_digest", "0 8 * * *",
    make_news_digest_job(researcher_tools, researcher_llm, send_to_leandro)
))

# In telegram_bot.py _split_prefix():
# if name in {"ana", "researcher", ...}:

New Agent Checklist

  • SKILL.md with frontmatter (name, llm, schedules, budget) and system prompt body
  • tools.py — @dataclass bound to stores and external clients
  • jobs.py — one make_<kind>_job builder per cron schedule
  • Tool schemas added to _<AGENT>_TOOLS_SCHEMA in main.py
  • Agent wired into amain(): skill loaded, LLM built, tools instantiated, jobs registered
  • Prefix added to _split_prefix() in telegram_bot.py for direct routing
  • Budget cap configured if needed
  • New model added to pricing.py if using a different model
